DCS-001 — Passenger could be boarded twice Critical
Module: Boarding pass / Boarding gate  ·  Status: Fixed & re-tested PASS

Steps to reproduce

  1. Complete the journey and board the passenger.
  2. Click "Generate boarding pass" again.
  3. Click "Board passenger".

Expected

The second boarding is rejected: "Duplicate boarding rejected: passenger is already boarded."

Actual (before fix)

"Boarding successful" was shown a second time. Re-issuing the pass silently reset the passenger's boarded status.

Business impact: In a production DCS, a passenger counted twice at the gate breaks the boarded headcount and the flight manifest.

Fix applied: Once a passenger is boarded, the boarding pass can no longer be re-issued.

DCS-004 — Boarding allowed after check-in was cancelled Critical
Module: Booking lookup / Boarding gate  ·  Status: Fixed & re-tested PASS

Steps to reproduce

  1. Complete the journey up to the boarding pass.
  2. Search again with a wrong PNR (BAD999).
  3. Click "Board passenger".

Expected

The failed search cancels the journey, the pass is withdrawn and boarding is refused.

Actual (before fix)

The journey showed NOT STARTED, but the boarding pass stayed on screen and boarding succeeded.

Business impact: A passenger without a valid check-in could be boarded.

Fix applied: A failed search now resets seat, baggage and pass. Boarding checks every step, not just the pass.

DCS-002 — Repeating check-in after boarding "un-boarded" the passenger High
Module: Check-in  ·  Status: Fixed & re-tested PASS

Steps to reproduce

  1. Board the passenger.
  2. Click "Complete check-in" again.

Expected

The request is refused and the status stays BOARDED.

Actual (before fix)

The status reset to PENDING, the seat and pass were cleared, and the passenger could board again.

Business impact: Boarding records can be reversed by mistake.

Fix applied: Check-in is locked after boarding.

DCS-003 — Seat could be changed after boarding High
Module: Seat selection  ·  Status: Fixed & re-tested PASS

Steps to reproduce

  1. Board the passenger in seat 12A.
  2. Click seat 12C.

Expected

The seat change is refused; the seat stays 12A.

Actual (before fix)

The seat changed to 12C and the boarded status was reset.

Business impact: The seat map no longer matches where the boarded passenger is sitting.

Fix applied: Seat changes are locked after boarding.

DCS-005 — Invalid baggage weight did not cancel the boarding pass High
Module: Baggage validation  ·  Status: Fixed & re-tested PASS

Steps to reproduce

  1. Complete the journey up to the boarding pass.
  2. Enter -5 kg and click "Validate baggage".
  3. Click "Board passenger".

Expected

The error is shown, the baggage status returns to PENDING, the pass is withdrawn and boarding is refused.

Actual (before fix)

The error was shown, but the status stayed VALIDATED, the pass stayed valid and boarding succeeded.

Business impact: A passenger could board with an invalid baggage record.

Fix applied: Every baggage re-check first cancels the previous validation and the pass.

DCS-006 — Blank baggage weight accepted as 0 kg Medium
Module: Baggage validation  ·  Status: Fixed & re-tested PASS

Steps to reproduce

  1. Check in and select a seat.
  2. Clear the baggage weight field.
  3. Click "Validate baggage".

Expected

The blank value is refused: "Enter a valid non-negative baggage weight."

Actual (before fix)

"Baggage validated: 0 kg" was shown.

Business impact: An agent who forgets to enter a weight would record "no checked bag" by mistake.

Fix applied: A blank weight is now refused.

DCS-007 — Occupied seat not marked as unavailable Low
Module: Seat map (accessibility)  ·  Status: Fixed & re-tested PASS

Steps to reproduce

  1. Open the seat map.
  2. Inspect occupied seat 12B with a keyboard or screen reader.

Expected

The seat is disabled and announced as unavailable.

Actual (before fix)

The seat was an active button and was only refused after it was clicked.

Business impact: Keyboard and screen-reader users get no warning before choosing the seat.

Fix applied: Occupied seats are now disabled and marked aria-disabled.

Key Automation Observations

  • Test reliabilityThe original scripts referenced screen elements that do not exist, so 5 of 7 tests failed for reasons unrelated to the product. The scripts now locate elements the way the application actually exposes them.
  • Assertion strengthPartial text checks were replaced with exact message checks, so a wrong or changed message is now caught.
  • MaintainabilityShared journey steps (check-in → seat → baggage → pass → boarded) are reusable building blocks; each verifies its own step before the next test step starts.
  • EnvironmentOne run timed out while the browser saved a video on a busy machine. Video is now optional; screenshots and step-by-step traces are still captured for every failure.

Recommendations

  • Add dedicated test identifiers to the on-screen step messages and status labels to make automation more robust.
  • Treat "BOARDED" as a final state everywhere in the product: any future feature that edits a passenger record should check it first.
  • Run the regression pack (DCS-001 to DCS-007) on every release so these defects cannot return.
  • Extend coverage to multi-passenger bookings, infants, and seat inventory shared between passengers when those features exist.
